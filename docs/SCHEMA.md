# Unified Two-Layer Schema v0.1 — design notes

The schema (`schema/uavsec_schema.json`, JSON Schema 2020-12) unifies all five datasets with three record kinds, chosen so that the *pairing* — the thing no existing dataset has — is a first-class object rather than an implicit join.

**Event** is one atomic observation from any source. The design principle is a small common core (identity, layer/sublayer, relative time, endpoints, unified label) plus a `metrics` block of the few numeric quantities that matter cross-source, plus a `native` block that carries every remaining source column untouched — so ingestion is lossless and nobody can accuse the benchmark of destroying information. The `layer` field is the two-layer split from the plan (`network` vs `autonomy`); `sublayer` refines it to the five attack surfaces (mesh, C2 link, intra-UAV bus / GNSS, sensor, controller, mission). `event_kind` names the natural granularity of each source: `flow` (UAVIDS-2025, UAV-CAS), `frame` (HCRL UAVCAN), `hop` (DATAMUt), `telemetry_sample` (UAV Attack Dataset), `flight` (UAV-EW-Bench). Timestamps are seconds relative to each scenario's own t=0 — absolute clocks across five unrelated captures are meaningless, and alignment happens at the window level, not the event level.

**AttackWindow** is a labeled attack interval within one scenario — the unit of cross-layer alignment. It carries the unified `attack_class` taxonomy (13 classes covering every native label across the five sources), ground-truth attacker where known, and class-appropriate `intensity` parameters (delay range for TDA, J/S for jamming, rate for flooding).

**CrossLayerPairing** is the novelty and the paper's data structure: one record chains a network window, the detector operating point θ, the worst-case residual budget of an evading attacker, the induced perturbation δ with a *named, versioned mapping*, the certificate output (certified MCR floor), and the empirical outcome for validation. The `pairing_basis` enum (`measured_same_platform` / `physics_model` / `synthetic_alignment`) is the honesty flag: it states, per record, whether the coupling was measured on one testbed (UAV Attack Dataset), derived through a stated physical model, or aligned by construction in simulation. Reviewers will ask exactly this question; answering it per-record is cheaper than answering it in rebuttal.

Per-dataset mapping status: **datamut_sim** and **uav_ew_bench_2026** are implemented and verified (`ingest/ingest_datamut.py`, `ingest/ingest_ewbench.py`; 54 hop events + 93,600 flight events currently in `data/staging/`). The remaining three follow the same pattern in Week 2: **uavids_2025** flows map with `layer=network, sublayer=mesh`, native 22 features into `native`, labels Blackhole/Flooding/Sybil/Wormhole into the taxonomy; **uav_cas** flows likewise with the config index as `scenario_id`; **hcrl_uavcan** frames map with `sublayer=intra_bus`, `protocol=uavcan_v0`, labels Flooding/Fuzzy/Replay; **uav_attack_whelan** telemetry maps with `sublayer=c2_link` or `gnss` per channel, and is the only source that will produce `pairing_basis=measured_same_platform` records — its GPS-spoofing runs carry both the network event and the measured `pos_error_m` degradation, which is what grounds the δ mapping empirically.
